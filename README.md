# تَـــلاقِ — منصة القبول والتسجيل والإدارة

منصة داخلية تدير دورة حياة الانضمام لكل المستويات (عضو قسم، قائد قسم، إدارة تنفيذية) عبر دعوة → اختبار قبول مخصص → اعتماد، مع حوكمة صارمة بالتسلسل، بوابة أعضاء بنظام تنبيهات، ونظام طلبات تلقائي بين الأقسام. مبنية على Next.js (App Router) + Prisma + PostgreSQL + Tailwind CSS 4، بهوية بصرية كاملة لعلامة **تَـــلاقِ**.

## الهوية البصرية

كل قسم/مستوى له لون خاص يظهر تلقائياً في كل الشاشات المرتبطة به:

| القسم / الدور | اللون |
| --- | --- |
| الفاونڈر / الإدارة العليا (Temptress) | `#341D2B` |
| الإدارة التنفيذية (CEO) | `#341D2B` (نفس هوية الإدارة العليا) |
| التسويق (Mahogany) | `#C34900` |
| الموارد البشرية (Beige) | `#EEF6DF` |
| التقنية (Green Sheen) | `#67C090` |

الخط: **Cairo** (عربي/لاتيني) عبر `next/font/google`. الشعار وملف الهوية الكامل في `public/brand/`.

## الحوكمة — تسلسل صارم بلا كسر

لا يوجد تسجيل عام إطلاقاً. كل حساب (عضو، قائد قسم، تنفيذي) يُنشأ حصراً عبر دعوة مقفلة بالاسم والإيميل → اختبار قبول → اعتماد:

```
الفاونڈر  ──يدعو──▶  حساب تنفيذي (CEO)
الفاونڈر / CEO  ──يدعو──▶  حساب قائد قسم
قائد القسم فقط  ──يدعو──▶  عضو داخل قسمه
```

- **الفاونڈر** لا يملك إضافة عضو داخل أي قسم مباشرة — فقط حسابات قيادية.
- **CEO** يملك نفس صلاحية الفاونڈر في إنشاء حسابات قادة الأقسام، لكن لا يمكنه إنشاء حساب CEO آخر.
- **قائد القسم** هو الوحيد القادر على دعوة أعضاء داخل قسمه.

كل اختبار قبول خاص بمستواه ويُحرَّر هرمياً بنفس التسلسل: الفاونڈر يحرر اختبار CEO، الـCEO يحرر اختبار القادة، وكل قائد قسم يحرر اختبار أعضاء قسمه فقط (`/admin/tests/executive`, `/admin/tests/leads`, `/admin/departments/[slug]/test`).

## حسابات الدخول وكلمات المرور المؤقتة

كل حساب يُنشأ عبر الاعتماد (قائد قسم، تنفيذي، أو عضو) يحصل على **كلمة مرور مؤقتة عشوائية** تُرسل بالبريد، ويُجبر على تغييرها فور أول دخول (`mustChangePassword`). الحساب الجذر الوحيد المستثنى هو حساب الفاونڈر المزروع يدوياً عبر seed.

## بوابة الأعضاء ونظام التنبيهات

بعد الاعتماد، للعضو حساب دائم يدخل به على `/member` ليرى تنبيهاته ويؤكد الاطلاع عليها. قائد القسم يصدر تنبيهاً (`/admin/departments/[slug]`) بسبب مكتوب يُرسل فوراً بالبريد (وبواتساب إن توفرت بيانات الاعتماد). **عند الوصول لـ 3 تنبيهات يُستبعد العضو تلقائياً** (`isActive = false`) ولا يعود يملك وصولاً فعلياً للمنصة.

## التشغيل محلياً

```bash
npm install
cp .env.example .env   # ثم عدّل القيم (خصوصاً DATABASE_URL)
npx prisma migrate dev
npm run db:seed        # يزرع الأقسام + بنوك الأسئلة الافتراضية + حساب الفاونڈر فقط
npm run dev
```

افتح `http://localhost:3000` — يحوّلك تلقائياً لصفحة الدخول.

### حساب الفاونڈر (الحساب الجذر الوحيد المزروع)

| البريد | كلمة المرور |
| --- | --- |
| super.admin@tlaqi.co | Tlaqi@2026 |

**غيّر كلمة المرور هذه قبل أي استخدام فعلي.** كل الحسابات الأخرى (CEO، قادة الأقسام، الأعضاء) تُنشأ من داخل المنصة عبر دورة دعوة/اختبار/اعتماد — لا بذور تجريبية لها.

## التكاملات الخارجية (اختيارية)

التطبيق يعمل بالكامل بدونها؛ في حال عدم ضبطها يتم تسجيل العملية في الـ console فقط دون كسر أي تدفق:

- **البريد الإلكتروني**: عبر [Resend](https://resend.com) — اضبط `RESEND_API_KEY` و `EMAIL_FROM`.
- **واتساب** (تنبيهات الأعضاء): عبر WhatsApp Cloud API — اضبط `WHATSAPP_TOKEN` و `WHATSAPP_PHONE_ID`.
- **Google Sheets** (السجل الرسمي للأعضاء المعتمدين + سجل أحداث التنبيهات/الاستبعاد): أنشئ Service Account وشارك الشيت معه (بتبويبين: `التسجيل` و`الأحداث`)، ثم اضبط `GOOGLE_SHEETS_CLIENT_EMAIL` و `GOOGLE_SHEETS_PRIVATE_KEY` و `GOOGLE_SHEETS_SPREADSHEET_ID`.

## البنية

- `src/app/login`, `src/app/change-password` — الدخول وتغيير كلمة المرور المؤقتة (NextAuth Credentials، يدعم حسابات User والأعضاء Member معاً)
- `src/app/admin` — لوحة الفاونڈر/CEO: إنشاء حسابات قيادية، اعتماد القيادة، نظرة شاملة
- `src/app/admin/departments/[slug]` — لوحة قائد القسم: دعوة أعضاء، اعتماد، Kanban الطلبات، قائمة الأعضاء والتنبيهات
- `src/app/admin/tests` — محرر بنوك الأسئلة الهرمي (تنفيذي/قادة/كل قسم)
- `src/app/invite/[token]` — صفحة المرشح لأي مستوى: تأكيد الهوية ← اختبار قبول ديناميكي (نجاح 80%) ← النتيجة
- `src/app/member` — بوابة العضو: الملف، التنبيهات، تأكيد الاطلاع
- `src/lib/workflow.ts` — منطق الأعمال: التسجيل، الاعتماد مع تزويد بيانات الدخول، التنبيهات والاستبعاد التلقائي
- `src/lib/testTracks.ts` — تحديد بنك الأسئلة المناسب وصلاحيات تحريره حسب التسلسل الهرمي
- `src/lib/brand.ts` / `src/lib/colors.ts` — نظام الألوان وتوليد الثيمات لكل قسم
- `prisma/schema.prisma` — نموذج البيانات (User, Member, Invite, TestTrack, TestQuestion, MemberWarning, Request...)
