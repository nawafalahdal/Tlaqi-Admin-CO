## ٢) النشر الآمن

1. **الفرع:** كل تغيير في فرع، يُدفع بلا `--force`، ولا يُعاد كتابة التاريخ.
2. **الفحوص المحلية قبل الدفع:** `npx tsc --noEmit`، `npx eslint .`، `next build`، ثم الانحدار (§٧).
3. **البناء يشغّل فحوصاً قبل `next build`** (`package.json` ← `build`): تغطية قوالب البريد، رسم الشعار، حصر الأقسام، سجلّ الأعضاء،
   ثم `migrate-deploy.ts`، ثم إعداد الذكاء الاصطناعي. **`migrate-deploy` يطبّق الترحيلات المعلّقة في بناء الإنتاج وحده**
   (`migrationPolicy.ts`: لا ترحيل من المعاينة، والبيئة المجهولة تُرفض).
4. **قبل نشرٍ فيه ترحيل:** خطة استعادة مكتوبة (نقطة استعادة Neon بحسب خطة الحساب) — ولا ترحيلٌ هدّام بلا موافقة.
5. **المعاينة:** انتظار حالة `READY` لبناء الفرع.
6. **الإنتاج:** «إعادة نشر» البناء الذي تحقّق في المعاينة إلى الإنتاج (Vercel ← Deployments ← Promote/Redeploy to Production) —
   **بموافقة المالك الصريحة**.
7. **بعد النشر مباشرة (§٣).**

### ٢-أ) قبل نشر `20261103120000_leadership_governance` — فحصٌ مسبق إلزامي (قراءةٌ فقط)

الترحيلُ يُسند كلَّ لجنةٍ عاملةٍ أو معلّقةٍ بلا قائدٍ إلى أقدم رئيسٍ تنفيذيٍّ نشط (ثم المؤسس)، ثم يُنشئ قيدَين. **إن وُجدت لجنةٌ كهذه ولا رئيسٌ ولا مؤسسٌ
نشط، فشل إنشاءُ القيد وفشل الترحيل** — فيتوقف بناءُ الإنتاج. يُشغِّل المالكُ أو من يملك الوصولَ قبل النشر (قراءةٌ لا تكتب):

```sql
-- ١) لجانٌ عاملةٌ أو معلّقةٌ بلا قائد — ستُسند بالخلافة عند الترحيل
SELECT count(*) FROM "Department"
WHERE "parentId" IS NOT NULL AND "committeeStatus" IN ('approved','suspended') AND "leadMemberId" IS NULL;
-- ٢) خَلَفٌ متاح: رئيسٌ تنفيذيٌّ أو مؤسسٌ نشط
SELECT "role", count(*) FROM "User" WHERE "isActive" = true AND "role" IN ('executive','super_admin') GROUP BY "role";
```

- إن كان (١) أكبر من صفرٍ و(٢) فارغاً: **لا نشر** — يُعرض على المالك أولاً.
- نقطةُ استعادة Neon قبل النشر (بيد المالك، بحسب خطة الحساب).
- `audit-data-integrity.ts` (قراءة) قبل النشر لحفظ صورةٍ للمقارنة.

## ٤) الرجوع (Rollback)

- Vercel ← Deployments ← النشر السابق السليم ← **Instant Rollback**. لا يمسّ القاعدة.
- سجّل معرّف النشر الحالي قبل كل نشر. نقطة الرجوع الحالية: `dpl_3sAQAXi3MTy6hR8MJLbnqd2NvZcv` (`abd92a5`) قبل P0،
  و`dpl_2V5YutD6U9uYyxHma3aqkEuARHSv` (`8243e1e`) قبل هذا التدقيق.
- إن كان النشر قد طبّق ترحيلاً: الرجوع بالشيفرة وحده لا يعيد القاعدة — يُتّبع خطة الاستعادة المكتوبة مسبقاً.
- **رجوعُ `20261103120000_leadership_governance`** (كلُّ خطوةٍ بموافقة المالك):
  1. **الشيفرة:** Instant Rollback إلى النشر السابق. الأعمدةُ والجدولُ الجديدة إضافيةٌ لا يقرؤها الإصدارُ السابق، فلا تضرّه.
  2. **القيدان** قد يرفضان بعضَ كتابات الإصدار السابق (لا يعرف القيادةَ بالخلافة — مثلاً تعيينُ قائدٍ للجنةٍ بيد القائم بالخلافة). إن ظهر ذلك في السجلات،
     يُرفعان — **بلا مساسٍ بأي صفّ بيانات**:
     ```sql
     ALTER TABLE "Department" DROP CONSTRAINT IF EXISTS "Department_active_committee_has_lead";
     ALTER TABLE "Department" DROP CONSTRAINT IF EXISTS "Department_single_committee_lead";
     ```
  3. **البيانات:** تبقى — `actingLeadUserId` وحالاتُ الإيقاف وصفوفُ `AccessRevocation` وأحداثُ التدقيق سجلٌّ لا يُحذف. والمغادرون والموقوفون
     حساباتُهم معطّلة (`isActive=false`) فيمنعهم الإصدارُ السابق أيضاً.
  4. **نقطةُ استعادة Neon** لا تُستعمل إلا لعطبٍ في البيانات نفسها — وهي تُسقط كلَّ ما كُتب بعدها، فقرارُها للمالك وحده.

## ٨) ممنوعات ثابتة
